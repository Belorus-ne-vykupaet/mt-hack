# Официальный baseline: CSV → CatBoost → дашборд

Адаптация к полному условию от 25 сентября 2026. Сейчас запускается **локальными процессами, без Docker**. Упаковка и проверка официального Docker-эмулятора оставлены на финальный этап по решению команды.

## Запуск

Из корня репозитория, Python **3.12+**, Node **22+**, pnpm:

```sh
python3.12 -m venv ml/.venv
ml/.venv/bin/python -m pip install -r ml/requirements.txt
ml/.venv/bin/python scripts/prepare-official-data.py
pnpm install --frozen-lockfile
pnpm hackathon
```

Для `uv`: `uv venv --python 3.12 ml/.venv && uv pip install --python ml/.venv/bin/python -r ml/requirements.txt`.
Можно использовать уже скачанный ZIP: `ml/.venv/bin/python scripts/prepare-official-data.py --archive /path/dataset.zip`.
Веса уже сохранены в `ml/artifacts/`; переобучение: `pnpm ml:train`.

- Сайт: http://127.0.0.1:4173/overview?source=official
- Python Backend Swagger: http://127.0.0.1:8093/docs
- Python ML Swagger: http://127.0.0.1:8092/docs
- REST/WS шлюз интерфейса: http://127.0.0.1:8081/api/v1/health
- Метрики и состояние: http://127.0.0.1:8081/api/v1/ml/status
- TCP NDTP: `127.0.0.1:9201`

`Ctrl+C` завершает дочерние процессы. Порты должны быть свободны. В обычном `pnpm demo` сохранён прежний учебный режим с автобусными маршрутами. Браузер запоминает выбранный источник; параметр `source=official` переключает его на API.

## Что обучено

`CatBoostRegressor(loss_function="MAE")`: 300 деревьев, глубина 5, seed 42. Отдельный `CatBoostClassifier` оценивает вероятность опоздания **>120 с** (200 деревьев, глубина 4). Вероятности пока не калиброваны. PyTorch-модель/ансамбль не используются в этом baseline; требование полного стека из условия остаётся задачей финального этапа, вместе с Docker.

Обучение — только `labels_train.csv`: **4434** примера. Проверка — только `labels_test.csv`: **353** примера. Test не используется для обучения, подбора числа итераций или early stopping.

| Локальная проверка | MAE, секунды |
|---|---:|
| CatBoost | 62.689 |
| Сохранение текущей задержки | 93.360 |
| Нулевая задержка | 103.337 |

Это **не score платформы**: параметры пересчёта MAE в score полностью не опубликованы. Машиночитаемые метрики, список признаков и важности: `ml/artifacts/metrics.json`. Важность признака не доказывает причинность.

Общий извлекатель признаков для обучения и сервиса: текущая задержка, горизонт, время суток, скорость за 2/10 минут, доля стоянки, возраст GPS, расстояние до целевой остановки, направление. Нет погоды, пробок и статуса дверей: этих признаков нет в обучающих CSV. Подключение текущей погоды к январскому архиву дало бы неверные признаки.

## Цель и защита от утечки

- Цель: **фактическое прибытие − плановое**, в секундах. Отрицательное значение — раннее прибытие; знак не обрезается.
- Целевая остановка: первая плановая запись в **(T+600, T+900]**. `target_stop_id` — это `tt_action_item_id`, ID конкретного прибытия, не постоянный ID остановки.
- Для train/test/validate текущая задержка берётся из выданного `cur_dev_s`.
- Только телеметрия `event_time <= T`. Будущие строки отсекаются даже при подаче готовой истории через API. `time_fact_begin` вообще не загружается извлекателем признаков.
- Для непрерывного архивного воспроизведения текущая задержка вычисляется только по уже наступившим фактическим прибытиям (`time_fact_begin <= T`); этот режим отличается от точечных подсказок `cur_dev_s` в проверочном наборе. Будущее расписание используется только как план.
- Некорректные скорости (>150 км/ч), невалидные GPS и отсутствующие измерения не заменяются выдуманными координатами. Пропуски передаются CatBoost как NaN.
- Временная зона CSV не указана организаторами. Для единообразного сравнения применён UTC-like clock без сдвига исходных часов; интерфейс явно показывает «часы CSV», а не МСК.

## Сабмит

`pnpm ml:train` также создаёт `ml/artifacts/submission.csv`: **151** строка, точные столбцы `sample_id;prediction`, разделитель `;`, порядок из `sample_submission.csv`. Проверяются полнота, дубликаты и конечность значений. Файл не отправляется на платформу автоматически и исключён из Git вместе с исходными данными. Для воспроизведения достаточно скачать официальный архив и выполнить обучение.

## Архитектура и интерфейс

```
Официальный CSV / NDTP TCP
          ↓
Python Backend :8093 — расписание, история, признаки, резервный режим
          ↓ HTTP /predict
Python ML :8092 — CatBoost задержка + вероятность
          ↓
Node UI gateway :8081 — существующие REST / WebSocket, планы, интеграции
          ↓
React UI :4173 — карта, аналитика, диспетчер
```

По умолчанию воспроизводится официальная test-телеметрия с `2026-01-06 17:50:00` со скоростью 1×. Можно задать `REPLAY_START="2026-01-06 12:00:00" REPLAY_SPEED=5 pnpm hackathon`. `REPLAY_SPEED=0` фиксирует срез для проверки. После конца архива часы останавливаются; поток не выдаётся за текущие городские данные.

В официальный прогноз включаются только ТС со свежим GPS (не старше 180 с) и целевой остановкой через 10–15 минут. Поэтому их число меняется. Номеров маршрутов в данных нет: `План ТС …` — группировка по `tr_id`, **не присвоенный номер городского маршрута**. На карте — последние GPS-следы, а не прямые линии между остановками. Геометрия загружается повторно каждые 10 с. Позиция автобуса берётся из наблюдения; предикт задержки не выдаётся за модель будущих координат.

В карточке показаны целевая остановка, точный горизонт, плановое время, подписанная задержка и вероятность. Промежуточная кривая на 0–15 минут отключена: baseline предсказывает одну остановку. Причины предупреждений — прозрачные правила по наблюдаемой скорости/стоянке/текущей задержке, не объяснение причинности ML. Команды диспетчера можно сохранить как план, но применить учебное влияние к официальному потоку нельзя.

ML отказал → persistence fallback с явным предупреждением, вероятность не оценена. Python Backend недоступен → шлюз сохраняет последний снимок, UI показывает потерю связи. После восстановления сервисы подключаются автоматически. Снимок общий для REST и WS, пересчёт не чаще одного раза в секунду, параллельные запросы объединяются. Серия наблюдений хранит максимум 240 точек (одна на 30 секунд); «с риском» также включает раннее прибытие менее −60 с. Истории NDTP ограничены 1500 пакетами на устройство и 1000 устройствами; таймаут неактивного TCP 60 с.

## NDTP без запуска Docker

Приёмник реализован по `docs/Emulator-and-Telematic-Packets-Specification.md` из официального архива: packed little-endian, NPL/NPH, handshake 6.2, CRC16/Modbus со сменой порядка байтов, TCP фрагментация/несколько кадров, повторное соединение. Поддержаны известные длины типов **0,2,8,10,15,16** (включая все автоматически генерируемые ячейки). Неизвестный тип отклоняется с учётом ошибки: длины не угадываются. Статус дверей IRMA пока не декодируется — полный бинарный layout в выданном документе не приведён.

По умолчанию TCP принимает пакеты для проверки, а UI показывает архив. Для живого режима нужны **актуальный план и mapping unit_id → tr_id**, поскольку штатная автогенерация эмулятора не следует историческому расписанию:

```sh
TELEMETRY_MODE=ndtp LIVE_PLAN_DIR=/absolute/path/current-plan pnpm hackathon
```

Каталог должен содержать `schedule_plan.csv` по официальной схеме, `traffic.csv` хотя бы с заголовком `tr_id,event_time,location_valid,lon,lat,speed,heading` и `unit-map.json` вида `{"1166336":122658}`. Приёмник привязан к loopback; внешний стенд и Docker-сетевое подключение на этом этапе не настраивались.

В NDTP режиме текущая задержка грубо оценивается при нахождении в пределах 50 м от плановой остановки на скорости до 3 км/ч. Это начальное приближение, не полноценный map matching. Нет совпадения — используется 0, как начальное отсутствие подсказки; улучшение сопоставления обязательно перед оценкой живого потока. Исторические фактические прибытия в NDTP режиме не используются. Автоматическая проверка идёт через локальные бинарные TCP кадры; официальный Docker-образ пока не запускался.

## Проверки и документация

```sh
pnpm ml:test
pnpm check
```

Тесты проверяют отсутствие утечки из будущего, строгий горизонт, ошибки GPS, формат сабмита, реальную загрузку весов, NDTP CRC/фрагментацию/reconnect и восстановление после отказа ML. Дополнительные проверки API/UI выполняются на локальном запуске. FastAPI автоматически публикует OpenAPI и Swagger; функции Python снабжены docstrings. Для HTML-документации: `PYTHONPATH=ml ml/.venv/bin/python -m pydoc -w transit_ml.features transit_ml.ndtp`.
