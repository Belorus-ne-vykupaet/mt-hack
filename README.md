## Для жюри: официальный режим

Основной способ запуска — **четыре контейнера**: React-сайт, Node API, Python Backend с NDTP-приёмником и Python ML. Нужны Docker Compose, Node.js 22+ и разрешённый организаторами архив данных. Обученные веса уже в репозитории; сырой архив и секреты в Git не включены.

```sh
python3 scripts/prepare-official-data.py --save-archive ml/data/official-dataset.zip
export API_TOKEN="$(openssl rand -hex 32)"
node scripts/start-official-docker.mjs -d
docker compose -f compose.official.yaml ps
```

Если архив уже скачан, замените первую команду на `python3 scripts/prepare-official-data.py --archive /путь/к/архиву.zip`. Ожидаются работающие `frontend`, `api`, `backend`, `ml`, а `api`, `backend`, `ml` — в состоянии `healthy`. Откройте [официальный обзор](http://127.0.0.1:8080/overview?source=official). Источник отмечен как **воспроизведение архивного test CSV**, часы архива — январь 2026 года. Swagger: [Backend](http://127.0.0.1:8093/docs), [ML](http://127.0.0.1:8092/docs); [HTML-документация Python](http://127.0.0.1:8080/docs/python/). Проверка: `curl -f http://127.0.0.1:8081/api/v1/health` и `curl -f http://127.0.0.1:8093/status`.

Команда `docker compose up --build` без `-f compose.official.yaml` запускает только **синтетический frontend**, не официальный контур. Полный сценарий и проверка NDTP-эмулятора — в [JURY_QUICKSTART.md](JURY_QUICKSTART.md), а доказательства по каждому критерию — в [матрице основного этапа](docs/22-criteria-evidence.md).

## Уточнение критериев после проверки

В официальной **`/analytics`** появился постоянный журнал **«Факт и сохранённый прогноз»**: первый прогноз для конкретной остановки, наблюдённое прибытие, ошибка и MAE по подтверждённым парам. История переживает перезапуск, неизвестные исходы не подменяются нулями. Для проверки потока добавлен сценарий **100 автобусов / 15 WS-клиентов / 30 минут** с потерей GPS и реконнектом. [Изменения, результаты и команды воспроизведения](docs/25-bi-and-fleet-validation.md).

Последующие исправления ускорили доставку новых GPS-пакетов в WebSocket и добавили разбор состояния дверей IRMA из официального NDTP-пакета. [Короткий повторный замер и границы проверки](docs/26-stream-and-door-check.md).

Для проверки раннего предупреждения откройте **[/docs/early-warning/](http://127.0.0.1:8080/docs/early-warning/)**: первый сигнал → плановый срок → наблюдённое прибытие для всех 96 эпизодов активной OSM-модели. Журнал Backend продолжает наблюдение после выхода цели из окна ML; отсутствие GPS не считается опозданием. В 95 подтверждённых нарушениях срока сигнал выпущен за 10,5–13 минут; Есть 7 эпизодов, где при сигнале ещё не было наблюдаемого опоздания. [Методика и полный знаменатель](docs/21-early-warning-evidence.md), [изменения и проверки](docs/24-observed-warning-outcomes.md).

В официальном потоке передаются наблюдаемые участки между остановками, средняя скорость и простой на них. Карта, список и карточка используют согласованный прогнозный риск, включая предупреждение классификатора при задержке меньше двух минут; карточка показывает наблюдаемый фактор. Первое предупреждение проверяет отдельное окно до возможного превышения порога опоздания: `план + 120 с`. ML-горизонт до плановой остановки остаётся 10–15 минут. [Изменения, проверки и границы доказательств](docs/23-criteria-completion.md).

## Страницы

- **`/overview` — обзор сети.** Интерактивная карта Москвы, транспорт и маршруты с цветовой индикацией риска, пунктуальность, динамика задержек, события и карточки объектов.
- **`/analytics` — аналитика.** Показатели сети, гистограмма задержек, распределение риска, факт и прогноз, рейтинг маршрутов. Рейтинг и распределение учитывают фильтры; общесетевые показатели подписаны отдельно.
- **`/dispatch` — диспетчер.** Автобусы маршрута, текущая и прогнозная задержка, отправка команд в тестовую диспетчерскую и советы GigaChat по выбранному маршруту.
- **`/reports` — отчёты.** Сводка наблюдённых срезов за день и история сохранённых дней.

Переключение **2D/3D** встроено в карту обзора. В официальном режиме столбцы показывают прогноз задержки ТС к целевой остановке, а кольца автобусов — риск. Наблюдаемые участки содержат измеренные скорость и простой; в деморежиме локальные риски участков синтетические.

Главный адрес `/` открывает интерактивную welcome-страницу. Из неё можно перейти в обзор сети, аналитику и диспетчерскую; рабочий обзор по-прежнему доступен напрямую по `/overview`. Welcome-страница также доступна через «О проекте» в боковой панели. На ней работают вращение сцены, пауза, учёт reduced motion и обе темы. Светлая и тёмная темы переключаются кнопкой в шапке или в настройках и сохраняются в браузере. Тема меняет карту, графики, подсказки и элементы управления. Все страницы адаптированы под мобильные экраны.

## Запуск

Нужен Node.js 22.13+ и pnpm 11.19.0 (версия закреплена в `package.json`).

```sh
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Открыть адрес, который напечатает Vite, обычно http://localhost:5173.

```sh
pnpm build      # production-сборка в dist/
pnpm preview   # просмотр собранного сайта
```

Шрифты и иконки поставляются локально. Картографические тайлы и подписи загружаются из [OpenFreeMap](https://openfreemap.org/quick_start/); карте нужен интернет и WebGL. При ошибке загрузки доступна кнопка повтора. Атрибуция OpenStreetMap/OpenMapTiles сохранена.

## Что работает

Поиск маршрутов, транспорта и остановок; фильтры маршрута и риска; выбор события → маршрута → транспортного средства; остановки и состав маршрута; масштабирование и возврат к обзору; включение слоёв; 3D-столбцы с подсказками; непрерывное обновление прогноза, плавный выбор горизонта и возврат к текущему состоянию. Выбор объекта и горизонт сохраняются между страницами.

## Данные и подключение бэкенда

При обычном `pnpm dev` без API работает **явно обозначенный демонстрационный поток**: 15 автобусных маршрутов Москвы по геометрии путей OpenStreetMap и 120 демонстрационных транспортных средств. Остановки и линии взяты из OSM; движение транспорта, задержки и риски синтетические. Каталог — снимок геоданных, а не актуальное расписание перевозчика. Официальный режим из раздела «Для жюри» использует отдельные Backend/ML, обученные веса ExtraTrees и NDTP-приёмник.

Сохранены REST/WS-контракты, сгенерированный клиент, адаптеры, обработка переподключения и синхронизация состояния. Для подключения реального сервиса:

1. Создать `.env.local` по `.env.example`.
2. Установить `VITE_DATA_SOURCE=api`, `VITE_API_URL` и `VITE_WS_URL`.
3. Согласовать `contracts/openapi.json` с API бэкенда и выполнить `pnpm api:generate` при изменении схемы.
4. Разрешить origin фронтенда через CORS на бэкенде.

Публичные адреса и флаги Vite встраиваются при сборке. Секреты в них хранить нельзя. Базовые карты настраиваются отдельно через `VITE_MAP_STYLE_URL` и `VITE_MAP_DARK_STYLE_URL`.

## Карта и локальные задержки

В 3D транспорт отображается объёмными моделями современного автобуса из [Quaternius Public Transport Pack](https://quaternius.com/packs/publictransport.html), лицензия CC0. Модель хранится локально, все автобусы используют общую геометрию. Они поворачиваются по направлению дороги и перемещаются при выборе прогноза. Цвет кольца под автобусом обозначает маршрут и сохраняется при смене темы, фильтра и горизонта прогноза; риск показывают линии и столбцы; нажатие открывает карточку транспорта. Это стилизованная модель, увеличенная на дальнем масштабе для читаемости. В 2D сохранены значки. [Источник и лицензия модели](public/models/README.md).

2D/3D переключается кнопкой на карте обзора без смены страницы. Старый адрес `/flow` перенаправляет на обзор с включённым 3D. Вращение: правая кнопка мыши или Ctrl + перетаскивание, на сенсорном экране — двумя пальцами; параллельное движение двух пальцев вверх/вниз меняет наклон. Панель кнопок вращения убрана.

Маршрут содержит независимо оцениваемые участки и автобусы. Общий статус — наибольший риск, а не цвет всей линии. На карте цвет участка и каждого ТС зависит от выбранного времени. В демо: №м3 — середина маршрута, №с344 — три отстающих автобуса на свободных путях, №е70 — конечная часть, №м6 — весь путь, №м40 — два раздельных участка. Карточка показывает число затронутых участков и ТС. Схема локальных рисков и движение синтетические, пути — OSM.

Поток обновляет прогноз каждую секунду без запуска воспроизведения. Ползунок задаёт любой горизонт 0–15 минут с шагом 0,01 минуты; значения интерполируются между текущей задержкой и прогнозом +15 минут. Это непрерывная визуализация демонстрационного прогноза, а не обученная ML-модель. API `GET /forecast` и событие `forecast.updated` передают геометрию и риск каждого участка в `segments`. Если backend не передаёт участки, карта не окрашивает весь маршрут его агрегированным риском.

Столбцы 3D привязаны к ближайшим остановкам своего маршрута. Подпись показывает название остановки, номер маршрута и задержку на соседнем участке (не время прибытия). Несколько участков, привязанных к одной остановке одного маршрута, объединяются по максимальной задержке. Высота отражает задержку, цвет — локальный риск. Название остановки, маршрут и задержка появляются только при наведении на столбец; постоянные подписи и верхняя памятка управления убраны.

При выборе горизонта автобусы плавно перемещаются по геометрии своего маршрута в 2D и 3D. Расчётная дистанция равна текущей скорости × времени горизонта за вычетом прироста задержки. Это оценка положения на фронтенде, не прогноз прибытия от ML-модели; остановки отдельно не моделируются. У конечной движение ограничено концом пути. Без подходящей геометрии или при нулевой скорости сохраняется исходная позиция. «Сейчас» возвращает текущую телеметрию. Настройка темы синхронизируется между открытыми вкладками.

## Подключаемый API и внешние сервисы

В 3D-карте добавлен отключаемый [слой текущей погоды Яндекс](docs/17-yandex-weather-layer.md): 13 точек Москвы, условные объёмные облака и дождь только возле точек с дождём. Нужен обычный серверный ключ API погоды; транспортный прогноз не меняет погодный слой.

[Запуск, контракт и сценарий показа жюри](server/README.md). `pnpm demo` запускает API-сервис и сайт на 4173. На странице `/integrations` можно подключить сайт к REST/WebSocket, увидеть состояние ML, получить погоду и проверить дорожный трафик при наличии серверного ключа. Диспетчер отправляет команды с проверкой revision, общего резерва и идемпотентности; журнал сохраняется на сервере, есть отмена.

Исполнитель и сетевые данные учебные. ML подключается через `ML_SERVICE_URL`, при ошибке остаётся базовый прогноз; автоматической оценки эффекта действий пока нет. Текущие внешние данные не примешиваются к архиву CSV. Ключи хранятся только на сервере. OpenAPI: `contracts/integration-openapi.json`. Базовая проверка проекта: `pnpm check`.

Объединены изменения `origin/kostya` (`8dcb63a`, `6bb37fa`) и `origin/zhenya` (`b88f19e`): обновлённый дизайн и диспетчерская очередь сохранены. `main` уже входит в эту историю.

Для внешних сервисов предусмотрены сценарии отправки, перезагрузки, отмены, отказа API и восстановления соединения. Open-Meteo может использоваться напрямую; Яндекс и ML работают через соответствующие серверные интеграции.

## Полное условие хакатона · объединённая модель команды

Модель из ветки `osm-extra-trees-51` с 64 признаками и историческим OpenStreetMap подключена к отдельному Python ML-сервису, Python Backend с приёмником NDTP и диспетчерскому дашборду. Локальный запуск: `pnpm hackathon` после подготовки Python и официальных данных. Полный Docker-запуск: `pnpm docker:official` после подготовки данных. Команда создаёт одноразовый токен и помещает только нужные CSV в локальный контекст сборки, даже если папка данных является символической ссылкой. Инструкция для жюри, метрики, защита от утечки, формат сабмита и ограничения: [ml/README.md](ml/README.md).

Дополнительные возможности и проверенные результаты: [отчёт по дополнительным фичам](docs/additional-features-report.md).
