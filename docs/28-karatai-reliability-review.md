# Проверка устойчивости из karatai

Проверено 28 сентября 2026 по локальному времени, 27 сентября по UTC. Изучена ветка `karatai` на коммите `6950111`; исправления устойчивости взяты из [acc17af](https://github.com/Belorus-ne-vykupaet/mt-hack/commit/acc17af2d24cbe16c91141c322a112092336c065). Исходный [отчёт коллеги](https://github.com/Belorus-ne-vykupaet/mt-hack/blob/6950111a9712a37fa79b481d7b5bee3f986ab489/reports/jury-reliability-2026-09-27.md) относится к Windows/WSL и другой версии модели. Его показатели не перенесены на текущую версию.

Основа проверки — `4fa4a55`, включающая `main` на `6b79cc9` и аудит источника действующего расписания. Сохранена модель **olya-extra-trees-osm-v1**, выбранная ранее; ML-эксперименты из остальных коммитов `karatai` не подменяют её. В отчёте нагрузки записаны SHA-256 проверенных исходников: измерялось рабочее дерево с исправлениями, а не неизменённый базовый коммит.

## Подтверждённые проблемы и исправления

| Проблема | Проверка до исправления | Результат |
|---|---|---|
| Неверный URL WebSocket upgrade | Необработанный `TypeError: Invalid URL` | Ответ 400, API продолжает отвечать |
| Входящий WS-кадр больше 64 КиБ | Необработанный `RangeError: Max payload size exceeded` | Закрывается только проблемное подключение |
| Общий трёхсекундный лимит большого исходящего пакета | Тест с продолжающейся отправкой обрывался после первого сообщения | Отдельный лимит каждого кадра и общий предел 30 с |
| HTTP ждёт ML-пересчёта | Параллельные запросы не завершались, пока модель удерживалась тестом | Последний целиком рассчитанный срез доступен сразу; статус и время публикуются вместе с новым срезом |
| Медленный клиент задерживает остальные | Новая вкладка не получала следующую рассылку до освобождения первого клиента | Не более одной отправки на клиента; остальные продолжают обновляться |
| Новому клиенту не отправляются неизменившиеся маршруты/ТС | После подключения второй вкладки список `route.updated` был пуст | У каждого клиента своя история доставленных версий и полный первый срез |

Первые четыре исправления перенесены из `karatai`. Исправление HTTP дополнительно распространено на `/warnings/audit` и `/analytics/forecast-evaluation`, где блокировка также воспроизводилась. Изоляция WS-клиентов и полный срез для новой вкладки добавлены при этой проверке. После задержки клиент получает последние изменения, удаления маршрутов/ТС и изменения участков; пропущенные секунды не накапливаются в очереди.

Дополнительно перенесены автоматический перезапуск контейнеров, ротация Docker-логов, переносимый запуск API, явная UTF-8 для нагрузочных данных и асинхронный сбор Docker RSS в измерителе. Скрипт проверки аварийного перезапуска теперь принимает имя отдельного Compose-проекта и локальный адрес: он не привязан к основному стенду.

## Автоматические проверки

- `pnpm check`: **155 тестов в 31 файле**, проверки типов приложения/API, lint и production build прошли.
- `PYTHONPATH=ml:src ../review-venv/bin/python -m pytest ml/tests tests/test_causality.py tests/test_submission.py -q`: **146 тестов** прошли. Для другого окружения замените путь интерпретатора на свою `.venv`.
- `OFFICIAL_BASE_URL=http://127.0.0.1:19080 pnpm exec playwright test --config playwright.official.config.ts tests/official-e2e/official.spec.ts`: **5 браузерных проверок** прошли на Docker-стенде, переключённом в архивный replay с перезапуском API. Проверены модель Оли, карта 2D/3D, ползунок, резервный режим и погода. Первый запуск после смены режима обнаружил сохранённый в API срез из нагрузочного NDTP; повторный запуск после очистки этого состояния перезапуском прошёл.
- Переносимый `scripts/start-api.mjs`: ответ health 200 на отдельном порту и корректное завершение по SIGTERM с кодом 0.
- Docker: собраны четыре сервиса, серверные healthcheck прошли. Работа измерялась на отдельном проекте `transit-karatai-review`, порты 19080/19081/19092/19093/19201, без внешних ключей.

В Python остаётся предупреждение устаревания интерфейса Starlette/httpx; сборщик предупреждает о крупных JS-файлах. Ошибок тестов и сборки нет. Windows в этой повторной проверке не использовалась.

**Ограничения:** минутный замер не подтверждает 30-минутную устойчивость, отсутствие утечки памяти или SLA менее 2 с. P95 Backend в этом коротком замере превышает 2 с, доставка GPS → WS — 6,48 с. Результаты Windows из `karatai` с P95 Backend около 8,2 с остаются отдельным свидетельством зависимости от окружения. Нужен длительный прогон на целевой машине; в этой задаче устранены воспроизведённые ошибки, но универсальный предел задержки не заявляется.

Тестовый план явно синтетический; он не является действующим планом организаторов. Ранних предупреждений за минуту не выпущено, поэтому этот замер не доказывает их качество или горизонт: эти правила проверяются автоматическими тестами. Источник действующего плана и официальный mapping остаются [отдельным ограничением](27-live-ndtp-plan-source.md). Закрытые CSV и ключи в Git не добавлены.

## Как повторить

После подготовки официального архива по [quickstart](../JURY_QUICKSTART.md) настройте отдельный локальный стенд. Пример для Bash:

```sh
python3 scripts/ndtp-fleet-load.py prepare --plan docker/local-data/karatai-fleet --vehicles 100 --interval 5
export COMPOSE_PROJECT_NAME=transit-karatai-review
export TELEMETRY_MODE=ndtp LIVE_PLAN_DIR=docker/local-data/karatai-fleet
export LIVE_PLAN_BIND_DIR=./docker/local-data/karatai-fleet
export OFFICIAL_UI_PORT=19080 OFFICIAL_API_PORT=19081 OFFICIAL_ML_PORT=19092 OFFICIAL_BACKEND_PORT=19093 OFFICIAL_NDTP_PORT=19201
export WEATHER_ENABLED=false GIGACHAT_AUTH_KEY= YANDEX_WEATHER_KEY=
node scripts/start-official-docker.mjs -d
python3 scripts/ndtp-fleet-load.py feed --plan docker/local-data/karatai-fleet --port 19201 --seconds 100 --warm-history 1800 --reconnect-at 45
```

Когда `/status` покажет 100 прогнозов, параллельно генератору запустите два измерителя в отдельных терминалах из корня проекта:

```sh
TRANSIT_SITE_URL=http://127.0.0.1:19080 BENCH_SECONDS=60 BENCH_WS_CLIENTS=10 \
  BENCH_OUTPUT=reports/recheck-stress.json node scripts/benchmark-jury-stress.mjs

TRANSIT_SITE_URL=http://127.0.0.1:19080 TRANSIT_API_URL=http://127.0.0.1:19081 \
  TRANSIT_BACKEND_URL=http://127.0.0.1:19093 TRANSIT_ML_URL=http://127.0.0.1:19092 \
  BENCH_COMPOSE_PROJECT=transit-karatai-review BENCH_RSS_MODE=docker \
  BENCH_SOAK_SECONDS=60 BENCH_SOAK_INTERVAL=5 BENCH_WS_CLIENTS=15 \
  BENCH_SOAK_OUTPUT=reports/recheck-fleet.json node scripts/benchmark-soak.mjs
```

После завершения измерителей отдельно проверьте аварийный перезапуск:

```sh
BENCH_ALLOW_DOCKER_MUTATION=1 BENCH_COMPOSE_PROJECT=transit-karatai-review \
  TRANSIT_SITE_URL=http://127.0.0.1:19080 BENCH_OUTPUT=reports/recheck-restart.json \
  node scripts/benchmark-api-restart.mjs
```

Этот последний сценарий намеренно завершает процессы Node только в контейнере API выбранного тестового проекта.
