# Раннее предупреждение: сигнал, нарушение срока, наблюдённое прибытие

Для жюри: [страница всех 96 эпизодов активной OSM-модели](../public/docs/early-warning/index.html), после запуска сайта — **/docs/early-warning/**. Она показывает часы первого сигнала, планового срока, фактического прибытия и момента, когда факт стал доступен. [Полный машинный аудит](../reports/early-warning-audit-2026-09-27-osm.json) содержит все события, включая пропуски и ложные сигналы; [прежний аудит Sasha-модели](../reports/early-warning-audit-2026-09-26.json) сохранён для сравнения.

## Что означает наступление задержки

Для конкретной плановой остановки срок нарушен, если фактическое прибытие **позже планового**. Начало нарушения этого срока — плановая граница; её нарушение подтверждается последующим наблюдением фактического прибытия. Допуск здесь **0 секунд**, произвольный двухминутный сдвиг не используется. Это восстановленная граница нарушения расписания, а не отдельно измеренная GPS-метка возникновения дорожного затора.

Различаются три события:

1. **Нарушение планового срока на целевой остановке.** При `факт > план` поле `delay_onset_at = план`; при раннем/своевременном прибытии его нет. Журнал подтверждает этот исход только после наблюдения факта.
2. **Опоздание более 120 секунд.** Отдельная целевая переменная классификатора и порог риска. Сигнал о таком риске при фактическом опоздании 107 секунд остаётся **ложным**, хотя плановый срок нарушен.
3. **Фактическое прибытие.** Оно завершает опоздание на остановку. Его время не приравнивается к началу нарушения срока и не используется для выпуска предупреждения.

Первый сигнал проверяет два окна: ML-цель `600 < план − T <= 900 с` и потенциальный двухминутный порог `600 < план + 120 − T <= 900 с`. Пересечение — `600 < план − T <= 780 с`. Поэтому сигнал находится в пределах 10–15 минут **до начала подтверждаемого нарушения планового срока**, а не только до двухминутного порога. При горизонте 780–900 секунд прогноз и риск доступны, первый алерт ожидает пересечения окон. Веса, инференс и CSV-сабмит не менялись.

## Завершённый эпизод без уже наблюдаемого опоздания

Официальный архив, ТС **131672**, целевая запись **53718793788**, 06.01.2026:

| Событие | Исходные часы CSV / значение |
|---|---|
| Последнее известное отклонение при сигнале | **−118 с**: автобус ещё не опаздывал по предыдущему прибытию |
| Возраст GPS | 9 с |
| Первый сигнал | **18:00:00** |
| Плановый срок целевой остановки | **18:11:00** |
| Порог опоздания >120 с | 18:13:00 |
| Фактическое прибытие | **18:13:31** |
| Факт стал доступен при воспроизведении | **18:14:00**, следующий 30-секундный срез |
| Измеренное опоздание | **151 с** |
| Сигнал до нарушенного планового срока | **660 с / 11 минут** |
| Сигнал до фактического прибытия | 811 с — отдельный показатель |

Вероятность риска при первом сигнале — 58,34%, точечный прогноз OSM-модели — 89,75 с; предупреждение разрешено вероятностным классификатором. Это не подгонка по будущему факту. Подтверждённых опозданий >120 с с известным `current_delay_sec_at_issue <= 0` в исходной выборке **7**. Остальные предупреждения не выдаются за первое возникновение сбоя на всём рейсе: они относятся к будущей конкретной остановке.

## Журнал наблюдаемых исходов

`GET /warnings/audit` Python Backend хранит неизменный первый сигнал и затем дополняет его фактическим исходом:

| Поле | Смысл |
|---|---|
| `issued_at`, `target_time` | Первый сигнал и плановая цель; не переписываются |
| `current_delay_sec_at_issue`, `predicted_delay_sec_at_issue`, `risk_probability_at_issue` | Что действительно было известно и предсказано при первом сигнале |
| `telemetry_age_sec_at_issue`, `observed_factor_at_issue` | Свежесть GPS и наблюдаемый фактор на тот момент |
| `outcome_status` | `pending` до плана; `awaiting_observation` после него без факта; `observed` после наблюдения прибытия |
| `actual_arrival_at`, `actual_delay_sec` | Фактическое прибытие и отклонение |
| `outcome_observed_at` | Когда факт стал доступен Backend; не подменяет время прибытия |
| `delay_onset_at`, `lead_to_delay_onset_sec` | Нарушенный срок и запас предупреждения до него; отсутствуют для своевременного/раннего прибытия |
| `warning_in_onset_window` | Попал ли сигнал в 600–900 секунд до подтверждённого нарушения срока |
| `risk_outcome` | Подтверждение или ложный сигнал именно для риска >120 с |
| `outcome_source` | `schedule_actual` в архиве; `ndtp_ordered_stop_visit` на бинарном потоке |

В архиве доступны только факты с `actual_ts <= T`. В NDTP используется наблюдённое посещение целевой остановки из упорядоченного сопоставления GPS с планом; будущие CSV-факты не читаются. **Отсутствие GPS не подтверждает опоздание.** Поздний повторный пакет стоящего ТС не передвигает зафиксированное прибытие.

Наблюдение продолжается, когда цель вышла из окна ML и активный алерт исчез из снимка. Исходы не поступают обратно в функцию выпуска сигнала. При перемотке архива назад будущие исходы скрываются. Журнал ограничен 5000 записями и живёт в памяти процесса; постоянное хранение между перезапусками не заявляется.

## Воспроизводимый аудит и полный знаменатель

После подготовки данных по [инструкции](../JURY_QUICKSTART.md):

```sh
docker compose -f compose.official.yaml run --rm --no-deps -v "$PWD/scripts:/app/scripts:ro" backend python /app/scripts/audit-early-warnings.py > reports/early-warning-audit-2026-09-27-osm.json
python3 scripts/build-warning-evidence.py
```

Страница в `public/docs/early-warning/` включена в репозиторий. После повторной генерации пересоберите frontend. Живой журнал — `http://127.0.0.1:8093/warnings/audit`.

Аудит повторяет исходные **91 срез** 17:50–18:35 с шагом 30 секунд, затем продолжает поток на **36 срезов** для наблюдения исходов, вплоть до факта 18:52:49. Новые сигналы хвоста не добавляются в исходную оценочную группу.

| Проверка | Результат |
|---|---:|
| Исходные плановые цели с фактом | **199** |
| Цели с положительным отклонением / >120 с | **166 / 120** |
| Первые предупреждения исходной группы | **96** |
| Наблюдаемые завершённые исходы | **96/96** |
| Нарушенные сроки среди предупреждений | **95** |
| Сигналы в окне до подтверждённого нарушения срока | **95/95**, запас **630–780 с** |
| Своевременные/ранние прибытия среди предупреждений | **1** |
| Подтверждённые опоздания >120 с / пропуски | **92/120 / 28** |
| Ложные сигналы именно риска >120 с | **4/96**, включая опоздания 107, 112 и 113 с |
| Нарушения планового/порогового окна | **0 / 0** |
| Изменения первого выпуска / утечки будущего исхода | **0 / 0** |
| Предупреждения после фактического прибытия | **0** |
| Подтверждённый риск без уже наблюдаемого опоздания при сигнале | **7** |

**95/95 — соблюдение горизонта среди предупреждённых нарушений, не полнота модели.** Предупреждены 95 из 166 целей с положительным отклонением. Метрика риска >120 с — **92/120 = 76,67%**, ложные сигналы — **4/96 = 4,17%**. Знаменатель не сужался до ТС с GPS или успешным прогнозом. В отчёте записаны версия активной модели `olya-extra-trees-osm-v1` и хеш соответствующего CSV, чтобы не смешивать результаты с прежним сабмитом.

[Живой NDTP-прогон той же модели](../reports/ndtp-live-window-osm-2026-09-27.json) через бинарный эмулятор организаторов сохранил первый сигнал за 691,4 с до планового срока и завершился наблюдённым прибытием через 821,4 с после сигнала. Опоздание составило 130 с. План и движение в этом прогоне учебные; при выпуске предупреждения отклонение на предыдущем участке уже наблюдалось.

### Отдельная проверка живого сценария без предыдущего опоздания

27 сентября повторён официальный Docker-эмулятор с `--previous-stop-offset-sec 30` и аудитом `--require-no-existing-delay`. Приёмник обработал 78 кадров без ошибок, из них 49 сопоставленных; отклонение на предыдущей остановке **−23 с**. В 47 сохранённых наблюдениях активная OSM-модель давала вероятность риска **8,97–10,83%**, и до нижней границы окна **первое предупреждение не появилось**. Прибытие после предупреждения поэтому не разыгрывалось; успешный ранний алерт этим сценарием не подтверждён. [Полный результат, прогнозы и состояние при завершении](../reports/ndtp-live-on-time-osm-2026-09-27.json).

Отчёт сохраняется и при неуспешном сценарии, включая причину, прогнозы и счётчики потока; ошибка остановки эмулятора не маскирует исходную причину. Это проверяется тремя автоматическими тестами. Для повторения создайте свежий план с указанным смещением, перезапустите Backend с ним и сразу запустите `audit-live-ndtp-emulator.py --require-no-existing-delay`; остальные параметры — как в [инструкции](../JURY_QUICKSTART.md#4-подача-потока-из-официального-ndtp-эмулятора). Прежний успешный сценарий с уже существующей задержкой сохранён отдельно.

Запас до фактического прибытия измерен отдельно: **745–1345 с**, медиана **1028 с**. Предоставленный test использовался для выбора модели; аудит подтверждает временную логику и наблюдаемость, а не новый независимый ML-score. Оценку выставляет жюри.

## Проверки причинности и NDTP

- [Проверки окон](../ml/tests/test_warning_window.py): границы 600/780/900 с, отсутствие будущего факта при выпуске и неизменность первого сигнала.
- [Проверки исходов](../ml/tests/test_warning_outcomes.py): раннее/своевременное прибытие, опоздание до 120 с и свыше, недоступность будущих наблюдений, перемотка, реальный Engine после истечения ML-окна.
- NDTP-тест оставляет GPS без обновлений до и после планового срока: исход неизвестен. После наблюдения целевой остановки исход подтверждается; повторные пакеты не меняют первый факт. Исторический CSV не используется.
- [Официальный Docker-эмулятор](../reports/criteria-live-verification-2026-09-26.json) подтвердил бинарный транспорт, участок, признаки, реальную модель и первый сигнал. Завершённые архивные эпизоды и автоматический NDTP-тест дополняют эту проверку; короткий smoke сам по себе не имитирует прошедшие 10–15 минут.
- [Прежний прогон того же официального образа](../reports/ndtp-live-window-2026-09-27.json) проведён до смены весов по настоящим часам с учебным текущим планом: первый сигнал за 682,3 с до плана, за 802,3 с до порога +120 с и за 812,3 с до наблюдённого прибытия; фактическая задержка 130 с. До посещения остановки журнал сохранял неизвестный исход. После последовательных GPS-пакетов остановка распознана, риск подтверждён, исходный момент сигнала не изменился. Это проверка живого временного контура, а не точности на действующем расписании перевозчика.
