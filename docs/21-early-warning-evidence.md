# Проверка горизонта раннего предупреждения

Официальное условие требует прогноз или алерт в окне T+10…15 минут до события, без предупреждений задним числом и на потоке. Цель сервиса — конкретная запись планового прибытия `tt_action_item_id`; окно задано строго как `600 < time_begin − T <= 900` секунд. Время из CSV сравнивается без перевода часового пояса. Телеметрия для признаков ограничена `event_time <= T`.

При каждом срезе исключается целевая остановка, фактическое достижение которой **уже наблюдалось** к T. В архиве это `time_fact_begin <= T` для той же записи плана. В NDTP это остановившийся в пределах 50 м автобус, увиденный за последние 30 минут; такой GPS-признак является эвристикой, а не достоверной записью о прибытии. Будущие фактические прибытия не используются для решения, выпускать ли сигнал. Время первого выпуска алерта хранится неизменным для пары ТС/цель; повторный расчёт обновляет величину прогноза, но не создаёт новый «первый» алерт. В карточке видны целевая остановка, плановое и ожидаемое прибытие, запас времени на момент первого сигнала и **наблюдаемый фактор**, который не выдаётся за причинное объяснение модели. `/warnings/audit` в Python Backend показывает первый выпуск и, по мере наступления события в архиве, его фактический результат.

В живом режиме входящий пакет известного `unit_id` вызывает перерасчёт автоматически, даже когда браузер не опрашивает API. Частые пакеты объединяются: не более одного расчёта в секунду. Неизвестный `unit_id` учитывается в `/status.ndtp.unmappedPackets` и не порождает ТС/алерт. Пакет с GPS старше 180 секунд оставляет последнюю позицию с пометкой `stale_gps` и не даёт прогноз; пакет с временем меньше последнего принятого для того же устройства отбрасывается. Некорректный CRC учитывается как ошибка. При отказе ML резервная оценка помечается как `fallback` и отдельно видна в журнале. Живой режим требует `LIVE_PLAN_DIR` с `schedule_plan.csv` и `unit-map.json`; без него Backend прекращает запуск вместо переноса январского расписания на текущую дату.

Воспроизведение после подготовки данных и официального образа по [инструкции для жюри](../JURY_QUICKSTART.md), без локального Python-окружения:

```sh
docker compose -f compose.official.yaml run --rm --no-deps -v "$PWD/scripts:/app/scripts:ro" backend python /app/scripts/audit-early-warnings.py > early-warning-audit.json
```

Сохранённый машинный результат: [`reports/early-warning-audit-2026-09-26.json`](../reports/early-warning-audit-2026-09-26.json).

Результат с моделью `sasha-extra-trees-v2` на официальном `test`, архивное время **06.01.2026 17:50–18:35**, шаг **30 секунд** (повторный запуск 26.09.2026): **91** срез, модель доступна на **91/91**; **95** уникальных первых предупреждений. Запас до **плановой** цели: **630–840 с**. Запас до **фактического прибытия** по этим 95 сигналам: минимум **745 с**, медиана **1028 с**, P95 **1186,2 с**, максимум **1345 с**. Ни один сигнал не выпущен после фактического прибытия или вне планового окна. JSON содержит для каждого первого сигнала `issued_at`, плановое и фактическое время, реальную задержку, запас до факта и запас до порога опоздания.

Правило события для оценки обнаружения: фактическое прибытие позже плана **более чем на 120 с**. Знаменатель зафиксирован до оценки сигналов: все уникальные записи плана с `time_begin` в интервале **(18:00, 18:50]** и известным фактом, включая ТС без пригодного GPS. Таких целей **199**, поздних событий **120**. Заранее предупреждены **92/120**, recall **76,67%**; **28** событий пропущены. Для **105** поздних событий хотя бы на одном срезе был готовый прогноз, из них предупреждены **92/105** (**87,62%**). Ложных предупреждений **3/95** оценённых сигналов (**3,16%**); это доля ложных среди алертов, а не специфичность модели. Первое превышение порога, `plan+120 с`, вычислено **ретроспективно из факта**: архив не содержит отдельного timestamp наблюдения этого нарушения. Запас до этого порога у истинных предупреждений: минимум **750 с**, медиана **780 с**, P95 **900 с**. Все числа относятся к проверенному интервалу и выбранной модели; предоставленный `test` участвовал в выборе модели, поэтому это не независимая оценка качества.

Бинарный TCP-тест проверяет фрагментацию кадра, CRC, повторное соединение, пакетный запуск расчёта без UI, границы ровно 600/900 с, неизвестный ID, потерю свежего GPS и запоздавший пакет.

**Официальный образ эмулятора, локальный Backend (26.09.2026).** Из поставленного архива загружен `ndtp-telemetry-emulator:1.0`; эмулятор отправил реальные бинарные кадры `G6CellNav00` по TCP в локальный Python Backend. Для проверки создан отдельный **синтетический текущий** `schedule_plan.csv` с соответствием `unit_id → tr_id`, а не использовано расписание январского архива. `/status`: `mode=official-ndtp`, `status=connected`, `frames=5`, `mappedPackets=3`, `ignoredUnits=2`, `errors=0`, `predictedVehicles=1`, `warningsIssued=1`, P95 расчёта **68,18 мс** на этом коротком прогоне. Первый сигнал выпущен за **859,1 с до плановой цели**; прогноз ExtraTrees **105,94 с**, вероятность класса «опоздание >120 с» **0,669** превысила порог алерта. Это подтверждает путь официальный эмулятор → TCP-приёмник → признаки → ML → журнал предупреждений без запроса браузера.

**Полный Docker-контур и браузер (26.09.2026).** Тот же образ направлен на опубликованный TCP-порт Backend-контейнера; Backend, ML и API прошли healthcheck, фронтенд открылся по HTTP 200. На момент [сохранённого JSON-снимка](../reports/ndtp-emulator-smoke-2026-09-26.json) Backend принял **52** бинарных кадра без ошибок, игнорировал неизвестный `unit_id`, выдал один прогноз и один алерт. API `/api/v1/alerts` вернул ID этого же предупреждения; WebSocket через сайт доставил `route.updated`, `vehicle.updated` и `alerts.snapshot` с тем же ТС без повторного HTTP-запроса. Chrome показал карточку `ТС 99116336`, остановку синтетического плана и активную подпись `ExtraTrees · NDTP`. Первый алерт появился за **860 с до плановой цели**. Повторный тест с десятью целями на 4-минутном шаге проверяет непрерывный поток и смену плановой цели во время длительного замера. Для синтетического live-плана нет фактического прибытия, поэтому запас до факта и точность алерта здесь **не измерены**; их отдельно оценивает архивный аудит выше. Результаты не гарантируют балл жюри.
