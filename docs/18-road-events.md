# Дорожные события и GigaChat

Во вкладке «Диспетчер» появился блок «Дорожные события». Выберите автобус и нажмите «Тестовое ДТП». Сервер размещает явно помеченное тестовое событие на дороге впереди автобуса, отправляет факты в GigaChat и показывает уведомление с рекомендацией и статусом «Задержка не определена». Уведомление также появляется в правой колонке обзора сети. «Убрать тест» удаляет тестовые события; автоматически они исчезают через пять минут.

Числовой прогноз, риск автобуса, ETA, расписание, ML-признаки и команды не изменяются. Неизвестная задержка хранится отдельно как `delaySec: null`, `delayStatus: "indefinite"`. Команды водителям автоматически не отправляются. При ошибке GigaChat событие остаётся видимым, а интерфейс прямо сообщает, что анализ недоступен.

## Реальный источник

Ключ Яндекс Погоды не подходит для дорожной ситуации. Серверные настройки в игнорируемом `server/.env`:

- `YANDEX_ROUTER_KEY` — доступ к API Получение деталей маршрута Яндекса. Адаптер запрашивает проезд по контрольным точкам впереди автобуса с текущими пробками и без них. Затор определяется только при совпадении геометрии, замедлении не менее чем в два раза и разнице от трёх минут. Это сигнал о заторе, **не подтверждение ДТП**.
- `TRAFFIC_EVENTS_URL` и необязательный `TRAFFIC_EVENTS_TOKEN` — адрес и Bearer-токен вашего лицензированного адаптера дорожных событий. Это контракт нашего адаптера, **не выдуманный публичный endpoint Яндекса**. Для конкретного корпоративного сервиса потребуется реализовать преобразование его ответа в указанный ниже формат.
- `GIGACHAT_AUTH_KEY`, `GIGACHAT_SCOPE`, `GIGACHAT_MODEL` — существующее серверное подключение GigaChat.

Без ключа/адаптера живое подключение помечено как отсутствующее. Демонстрация доступна отдельно и никогда не выдаётся за сведения Яндекса.

Официальные спецификации:
- https://yandex.ru/maps-api/docs/router-api/request.html
- https://yandex.ru/maps-api/docs/router-api/response.html
- https://yandex.ru/maps-api/docs/js-api/examples/cases/traffic.html

Документированный Router API предоставляет геометрию и время проезда. Его ответ не содержит ленту ДТП. Слои пробок и событий JavaScript API предназначены для отображения на Яндекс Картах; они не используются как серверный источник событий в этом проекте.

## Контракт адаптера событий

GET `TRAFFIC_EVENTS_URL`, заголовок `Authorization: Bearer ...` при заданном токене:

```json
{
  "items": [{
    "id": "provider-event-123",
    "kind": "accident",
    "position": {"lon": 37.62, "lat": 55.75},
    "bearingDeg": 90,
    "description": "Одна полоса перекрыта",
    "observedAt": "2026-09-27T12:00:00Z",
    "expiresAt": "2026-09-27T12:05:00Z"
  }]
}
```

`kind`: `accident`, `closure`, `roadworks`, `congestion`. `observedAt` — время последнего подтверждения источником; данные старше десяти минут игнорируются. Истечение обязательно; неверные координаты и неподдерживаемые события отбрасываются. `bearingDeg` необязателен, но нужен для надёжного исключения встречной полосы. Источник присваивается сервером; вход не может выдать себя за тестовое событие.

## Сопоставление и обновление

На ближайшем подходящем участке геометрии автобуса строится коридор до 3 км по направлению к следующей целевой остановке или по курсу GPS. Пропускаются устаревшая телеметрия, неподходящая геометрия и неизвестное направление. Событие должно быть на 40–3000 м впереди, в пределах 30 м от линии. Если источник указал направление, встречные события исключаются. На развязках и близких параллельных дорогах координат недостаточно для гарантированного определения полосы; перед производственным применением нужны идентификаторы дорожных рёбер/направлений источника.

Пока открыта страница, интерфейс опрашивает `/api/v1/traffic/notifications` каждые пять секунд. Сервер запускает максимум одну проверку внешних источников раз в две минуты, не блокируя ответ уведомлений. До трёх запросных задач выполняются одновременно; запросы имеют таймауты. Повторный анализ одинакового события кэшируется на десять минут. Пропавшие события удаляются после успешной проверки; при сбое источника сохраняются только до своего срока годности и показывается ошибка подключения. Это мониторинг для открытого приложения, не отдельный круглосуточный фоновый сервис.

Текущая дорожная обстановка и архивная телеметрия могут относиться к разным датам. Их сопоставление служит дополнительной функцией интерфейса и не объясняет историческое опоздание. Этот контекст явно передаётся GigaChat.

## Внутренний API

- GET `/api/v1/traffic/notifications` — состояние источника, уведомления, `usedInModel: false`.
- POST `/api/v1/traffic/demo` с `{"vehicleId":"vehicle-122048"}` — тестовое ДТП и анализ.
- POST `/api/v1/traffic/demo` с `{"clear":true}` — удалить тесты.

Права доступа и защита Origin общие с остальным API; публичное чтение не разрешает создавать тесты без авторизации. Ключи остаются на сервере и не возвращаются клиенту. Состояние временное, после перезапуска тестовые события исчезают.
